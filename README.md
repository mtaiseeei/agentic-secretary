# agentic-secretary

技術者・AI活用に慣れた利用者向けのAI秘書です。会話、診断、実行結果、developer handoffで、
正式名称、command、path、error、証拠、残課題を先に示します。

記憶・一般プロジェクト・選択したChatworkルーム・Google Chat通常スペースは、利用者ごとの
1つのprivate GitHub repoで管理します。Chatwork／Google Chatのwizard、OAuth scope、同期境界、
secret保護、workspace境界は共通基盤であり、hostやeditionごとに分岐しません。

## Install: Claude Code Desktop App / CLI

Claude Codeのインストール経路は次のとおりです。

```text
/plugin marketplace add mtaiseeei/agentic-secretary
/plugin install agentic-secretary@agentic-secretary
/secretary
```

GitHub repositoryと`origin`、記録済みbaseline pushはprivateのまま成立しています。現在の追加commitのpush、
public設定、release公開、未承認hostへのinstallはこの作業では行いません。

## Install: Codex App

1. Plugins Directoryで `agentic-secretary` marketplaceを追加または選択します。
2. plugin detailsから `agentic-secretary` をinstallします。
3. install後に新しいchatを開始し、`$secretary` または自然な依頼で呼び出します。

`AGENTS.md`、skills手動コピー、`config.toml` はrepository-localの開発・隔離test・fallback専用です。
正式な配布経路の代わりにはなりません。

## Architecture

```text
plugins/secretary/              # host-independent common core
  .claude-plugin/plugin.json    # Claude Code manifest
  .codex-plugin/plugin.json     # Codex manifest
  rules/                        # safety, evidence, Markdown, agentic 4-surface style
  skills/                       # shared skill semantics
  scripts/                      # workspace, update, OAuth and sync safety
  skills/*/assets/wizard/       # common Chatwork / Google Chat wizard

adapters/                       # host-specific integration only
  claude-code-desktop-app/
  claude-code-cli/
  codex-app/
  codex-cli/

scripts/agentic-*.mjs           # adapter validation, host aggregation, install-plan output
```

Codex用repo marketplaceは `.agents/plugins/marketplace.json`、Claude用marketplaceは
`.claude-plugin/marketplace.json` です。両方とも同じ `plugins/secretary/skills/` 15件を参照し、
host別のskillコピーは持ちません。

各skillは、読み込まれた `SKILL.md` 自身の実ファイル絶対pathから `plugins/secretary/` を解決します。
`${SECRETARY_PLUGIN_ROOT}` はその検証済み結果だけを保持し、未設定のClaude専用環境変数、空path、相対path、
現在directoryからの推測をcommandへ渡しません。host固有の前提一覧は
[`plugins/secretary/host-inventory.json`](plugins/secretary/host-inventory.json)にあります。

開発依頼は別Pluginの [Agentic Harness 0.5.0](https://github.com/mtaiseeei/agentic-harness) へ接続します。

|---|---|---|---|
| Claude Code | `agentic-harness` | `harness@agentic-harness` | `/harness` |
| Codex | `agentic-harness-local` | `harness@agentic-harness-local` | `$using-harness` / `$harness-loop` |

通常はどちらのhostでも「〇〇を作って」と話すだけで起動できます。導入詳細は `build` skillが
現在のhostに合う手順だけを案内します。

Edition-specific content is limited to four expression surfaces: conversation, diagnosis, report,
and developer handoff. Distribution identifiers and host adapters are integration metadata.
Wizard files, DOM/copy, OAuth scopes, sync behavior, and safety rules remain byte-identical to the
neutral base and are protected by `scripts/sprint-033-test.mjs`.

## Common safety contracts

- A workspace write is confined to the confirmed root; escaping symlinks are rejected before side effects.
- Chatwork API Token is entered by the user only in GitHub Repository Secrets. The wizard and conversation never receive the value.
- Google OAuth strict secrets stay in the local wizard session and are sent to GitHub Repository Secrets through `gh` stdin.
- Only selected Chatwork rooms and Google Chat `SPACE` resources are synchronized.
- Diagnosis is read-only. Update starts only after an explicit confirmation and a push-free protection commit.
- Equal-version and downgrade requests stop without modifying plugin, workspace, Git, settings, ledger, or migration state.
- A live gate that is missing, unauthenticated, or not explicitly approved remains `incomplete` / `external-live-gate-unavailable`.

### Google Chatをつなぐ（少し高度な設定）

Google Workspace管理者がGoogle Cloud projectを用意し、OAuth Audienceを `Internal`、Application typeを
`Desktop app` に設定します。People APIは連絡先にない同僚名を常に解決できるわけではないため、表示名が
取得できない場合は共通coreのfallbackを使います。実際のOAuth設定・Repository Secret登録・初回同期は、
利用者の明示同意後にwizardから行う外部操作です。2026-07-22に実環境で確認済みです。

## Local validation

```bash
node scripts/sprint-033-test.mjs
node scripts/agentic-host-gate.mjs --mode offline
bash scripts/agentic-regression.sh
```

The live gate requires separate approval for each host installation and does not run as part of the
offline suite.

After one host and its external side effects have been approved, the shared runner accepts only an
exact approval manifest and writes one new result file without overwriting an existing record:

```bash
node scripts/agentic-live-host-gate.mjs \
  --host <required-host-id> \
  --approval /absolute/path/to/approval.json \
  --output /absolute/path/to/new-sanitized-result.json
```

The version 2 approval must name the matching host, adapter runner, app/CLI surface, all twelve
checks, an expiry, a digest-bound executable and driver artifacts, and the exact isolation
contract. That contract requires a synthetic HOME inside a runner-owned temporary workspace, a
digest-matched read-only plugin copy, OS sandbox or host-guaranteed path-scoped permission, a
recorded Write/Edit denial against a controlled outside-workspace canary, a Bash-free minimal tool
list, bounded inspected targets, and cleanup after both success and failure.

The runner forces the driver cwd, HOME, TMPDIR, plugin reference, workspace, and canary to its
isolated paths. It independently compares the plugin source/copy and canary before and after, then
removes the workspace, synthetic HOME, plugin copy, and canary before writing the result. A
sanitized driver claim without the structured isolation report and runner-observed invariants is a
FAIL. Retained results omit the actual executable, arguments, raw stdout/stderr, credential values,
and real filesystem paths. Without `--approval`, the runner performs no host operation and exits 2
with `external-live-gate-unavailable`.
